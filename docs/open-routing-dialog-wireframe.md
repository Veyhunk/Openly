# 打开接管弹窗：极简两步设计

## 1. 目标与范围

打开接管弹窗只服务于一次文件或链接打开请求。首屏帮助用户快速选定应用，第二屏只展示该应用可执行的打开方式。页面减少标题、说明、图标和重复按钮，让文件目标、默认应用、候选应用与打开方式形成一条清晰路径。

默认流程仍是两步：

```text
应用列表 → 打开方式 → 执行并关闭
```

高级模式是偏好设置中的可选布局，将左侧应用列表和右侧打开方式合并到一页；它不改变默认两步流程的视觉基线。

## 2. 设计原则

| 原则 | 设计决定 |
|---|---|
| 内容优先 | 文件名、完整地址、默认应用和候选应用优先获得空间 |
| 低认知负担 | 首屏只保留搜索、推荐/全部和 App 选择；第二屏只保留返回与打开方式 |
| 原生一致 | 使用 SwiftUI 原生按钮、文本字段、滚动容器和系统颜色 |
| 紧凑但可操作 | 应用项缩小视觉间距，点击热区仍保持至少 44pt 高 |
| 方向明确 | 原默认应用和原默认打开方式用同一套强调色边框提示 |
| 可恢复 | 返回只回到 App 网格，保留当前请求、搜索词和滚动位置 |

ui-ux-pro-max 的 SwiftUI 专项搜索没有得到匹配结果，本方案采用 macOS 原生控件与通用 UX 规则作为回退：模态窗口内保留可见键盘焦点、交互控件提供可访问名称、选中状态不能只依赖颜色。

## 3. 窗口基线

| 项目 | 设计值 |
|---|---:|
| 默认宽度 | 760pt，约容纳 7 个 App 项 |
| 最小宽度 | 680pt；低于此宽度时保持水平滚动，不压缩 App 名称到不可读 |
| 默认高度 | 520pt |
| 页面内边距 | 20pt |
| 顶部目标区 | 72–88pt |
| 搜索栏区域 | 42–48pt |
| App 网格列数 | 5 列，列宽弹性，间距 12pt |
| App 项垂直间距 | 8–12pt |
| 打开方式卡片 | 52–64pt 高；无图标 |
| 主文本 | 系统 `.body` / `.callout` |
| 辅助文本 | 系统 `.caption`，保持足够对比度 |

窗口可调整大小。宽度不足时 App 区域允许水平滚动，第二页的方式卡片也允许水平滚动；滚动区域不能遮挡底部取消操作和键盘焦点。

## 4. Page 1：选择打开应用

### 4.1 线框

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  example.md                                             [▣  VS Code  ] │
│  file:///Users/[User]/Documents/example.md               [        ] │
├──────────────────────────────────────────────────────────────────────────────┤
│  [ 搜索应用                                             ] [ 推荐 | 全部 ]     │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ◇ VS Code       ◇ Cursor        ◇ Chrome        ◇ Preview       ◇ TextEdit │
│     Code            Cursor          Google Chrome    预览            文本编辑 │
│                                                                              │
│   ◇ Devin          ◇ IINA          ◇ Notes         ◇ Quark         ◇ 其他…   │
│     Devin           IINA            备忘录          Quark            选择应用 │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  选择应用后进入打开方式                                          [取消]      │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 区域规则

**目标区**

- 左侧分两行
  - 第一行展示文件名或链接摘要，单行省略。
  - 第二行直接展示完整地址或完整文件路径，最多两行，支持复制。
- 右侧刚好两行高
  - 显示原默认应用快捷按钮：显示应用图标和名称 
    - 使用主题亮色边框，不要卡片背景色
- 当前没有可用原默认应用时，右侧保留空白，不显示占位卡片。

**筛选区**

- 搜索字段同时匹配应用名称、Bundle ID 和支持的扩展名。
- “推荐”只显示支持当前请求内容的应用，并把原默认应用置于候选前部。
- “全部”显示所有已扫描应用和“其他应用…”入口。
- 推荐/全部是分段控件，不使用下拉菜单。

**App 区**

- 不使用背景卡片，不使用阴影，不使用大面积容器填充。
- 每项由系统应用图标、应用名称组成，图标 44–52pt，名称最多两行。
- 原默认应用使用 2pt AccentColor 边框，并显示“原默认”小标签；边框是辅助提示，名称仍必须完整表达状态。
- App 项点击后立即进入 Page 2；只有一个可行打开方式且偏好允许自动打开时直接执行。
- 搜索无结果时显示空状态和“查看全部”动作。

### 4.3 交互

| 操作 | 行为 |
|---|---|
| 输入搜索 | 结果实时收敛，焦点保持在搜索框 |
| 切换推荐/全部 | 保留搜索词与滚动位置 |
| 点击 App | 进入 Page 2；单一方式时直接执行 |
| 点击默认打开 | 使用恢复记录中的原默认应用，绕过选择步骤 |
| Escape | 关闭本次打开请求 |
| Tab | 搜索 → 推荐/全部 → App 项 → 其他应用 → 取消 |
| Return | 激活当前焦点 App 或默认打开按钮 |

## 5. Page 2：选择打开方式

### 5.1 线框

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  [‹ 返回]  example.md                                  [▣ VS Code]       │
│                 file:///Users/[User]/Documents/example.md                    │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  ┌────────────────────────────────────────────────────────────────────────┐  │
│  │ 最近活动窗口                                                          │  │
│  │ 使用 VS Code 最近活动的窗口打开                                       │  │
│  └────────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  ┌────────────────────────────────────┐  ┌────────────────────────────────┐  │
│  │ 新窗口                             │  │ Window — project-a             │  │
│  │ 在新窗口中打开                     │  │ 切换到此窗口并打开             │  │
│  └────────────────────────────────────┘  └────────────────────────────────┘  │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  点击打开方式即可执行                                               [取消]  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 区域规则

**顶部目标区**

- 左侧为“返回应用”，返回按钮带文字和返回语义，不使用孤立图标。
- 中间显示文件名或链接摘要。
- 右侧显示已选 App 图标与名称，两行高度与左侧对齐。
- 下一行直接展示完整地址或路径，最多两行，支持复制。

**方式卡片**

- 卡片不显示 SF Symbol 或应用图标，只显示标题和一行描述。
- 卡片高度 52–64pt，水平内边距 12pt，圆角 8–10pt。
- 一个方式时使用单列并撑满可用宽度，形成明确主操作。
- 多个方式时在可用宽度内平均分配；卡片不足以保持可读宽度时允许水平滚动。
- 原默认打开方式沿用 AccentColor 边框和“原默认”标签。
- 浏览器 Profile、窗口、标签组、无痕和临时会话使用同一张卡片结构，不添加图标区分。
- 加载已有窗口时，卡片区域显示轻量进度信息；失败信息就近放在对应 Profile 或窗口分组下。

### 5.3 交互

| 操作 | 行为 |
|---|---|
| 点击方式卡片 | 立即执行，窗口先收起，成功后关闭选择器 |
| 返回应用 | 回到 Page 1，保留请求、搜索词和已加载应用 |
| 方式加载中 | 其他已可用方式仍可点击；加载状态不阻塞默认/新窗口 |
| 目标失效 | 保留选择器并显示错误，要求重新选择 |
| Escape | 返回 Page 1；在 Page 1 再按一次关闭请求 |
| Tab | 返回应用 → 方式卡片 → 取消 |
| Return | 激活当前聚焦的方式卡片 |

## 6. 高级模式关系

高级模式开启后使用同一套目标区、App 项、方式卡片和状态标记。页面按 App 分行，每一行同时展示该 App 的全部可行打开方式；用户不需要先选 App 再等待右侧内容切换。

```text

┌──────────────────────────────────────────────────────────────────────────────┐
│  example.md                                             [▣  VS Code  ] │
│  file:///Users/[User]/Documents/example.md               [        ] │
├──────────────────────────────────────────────────────────────────────────────┤
│  [ 搜索应用                                             ] [ 推荐 | 全部 ]     │
├───────────────┬──────────────────────────────────────────────────────────────┤
│ App            │ 该 App 的全部打开方式                                       │
├───────────────┼──────────────────────────────────────────────────────────────┤
│ VS Code        │ [最近活动窗口] [新窗口] [project-a 窗口]                    │
│ Cursor         │ [默认打开] [新窗口] [project-b 窗口]                        │
│ Chrome         │ [默认 · 您的 Chrome] [新窗口] [无痕] [已打开窗口]           │
│ Preview        │ [默认打开]                                                   │
└───────────────┴──────────────────────────────────────────────────────────────┘
```

### 6.1 行式布局规则

- 每个 App 占一行，左列固定显示系统图标和名称，右列显示该 App 当前可行的全部打开方式。
- 右侧方式卡片使用紧凑横向排列；只有一个方式时撑满该行的剩余宽度。
- 方式过多时只在该行内部横向滚动，不能把其他 App 行一起横向移动。
- 原默认 App 和原默认方式仍使用同一套边框标记。
- Chrome 的 Profile、窗口、标签组和无痕方式按 Profile 分组显示在同一 App 行内。
- VS Code 的最近窗口、新窗口和已有窗口直接并列显示。
- App 行之间使用 12–16pt 垂直间距和轻量分隔线，不使用大背景卡片。
- 筛选“推荐/全部”作用于 App 行；搜索同时匹配 App 名称、Profile 名称、窗口标题和打开方式描述。

高级模式只是把 Page 1 的应用候选和 Page 2 的方式卡片改成按行展开；地址、默认标记和键盘顺序保持一致。默认设计仍优先使用两步流程，避免首次使用时同时面对所有 App 的高级选项。

## 7. 视觉与可访问性验收

- 使用系统语义色和系统字体，适配浅色、深色、提高对比度和减少透明度。
- App 图标是身份信息，不作为唯一状态提示；原默认状态同时提供文字标签和边框。
- 所有按钮、App 项和方式卡片提供可访问名称；装饰性图标隐藏于辅助功能树。
- 键盘焦点保持清晰可见，不能被水平滚动区域或底部操作栏遮挡。
- 搜索框、分段控件、App 项和方式卡片都能通过键盘完成操作。
- 卡片和 App 项的点击热区不小于 44pt 高；视觉图标可以小于热区，但不能缩小点击区域。
- 正文与辅助文字维持足够对比度；边框在浅色和深色模式下都可识别。
- 加载、失败、不可用和已选状态同时使用文字、边框或控件状态表达，不只依赖颜色。

## 8. 验收清单

- [ ] Page 1 默认宽度约容纳 7 个 App，应用项无背景卡片。
- [ ] Page 1 右上角默认打开按钮保持两行结构。
- [ ] 完整地址在两页都直接展示并可复制。
- [ ] Page 2 方式卡片没有图标，单卡片可以撑满右侧。
- [ ] 多卡片在窄窗口中支持横向滚动且焦点不丢失。
- [ ] 推荐/全部切换不丢失搜索词和滚动位置。
- [ ] 原默认 App 与原默认方式使用一致的边框标记。
- [ ] Chrome Profile、窗口、标签组和 VS Code 窗口仍能表达完整描述。
- [ ] 普通模式、轻量模式和高级模式的返回、取消、失败恢复路径一致。
