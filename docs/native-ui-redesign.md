# Openly 原生界面与交互重设计

> 日期：2026-10-27 · 状态：设计提案，供后续实现与验收使用。
> 基线：现有 README、任务记录与 Swift 源码；平台为 macOS 14+，SwiftUI + AppKit，SPM 构建。
> 本文的现状判断来自静态检查。输入、焦点、窗口缩放等运行表现仍需实机复现；线框图中的应用、数量和结果均为示例。

## 1. 需求重新分析

Openly 的核心价值是让用户知道文件将由谁打开，并可靠地修改这个选择。界面应持续回答三个问题：当前状态是什么、这次会改变哪些内容、实际改变成功了多少。

主要使用者是需要整理文件打开方式的 Mac 用户。高频任务是查找某种文件类型并更换默认应用；集中整理时，用户从某个应用出发管理多种格式。备份、恢复和单文件排查属于辅助任务。

新增“打开接管”：用户选择由 Openly 接收的文件后缀或网页链接，每次打开时再选择应用及其个人资料、窗口或标签组。配置界面负责接管范围，轻量选择器负责本次打开目标。技术可行性和测试证据统一维护在[接管技术报告](open-routing-feasibility.md)。

### 1.1 功能与原生设计适配

| 用户任务 | 应保留或补齐的能力 | 推荐原生模式 | 选择理由 |
|---|---|---|---|
| 查某种文件由谁打开 | 搜索扩展名、描述、默认应用，按分类与默认应用来源筛选 | `Table` + 工具栏搜索 + 筛选菜单 | 多字段需要横向比较；表格支持排序、键盘选择与多选 |
| 为一种格式更换应用 | 查看当前应用、选目标、确认范围、核验结果 | 窗口附属 Sheet + 单选 List | 选择与提交分开，保留原列表上下文 |
| 按应用整理格式 | 查看应用信息、声明支持的格式、当前默认格式 | 应用 List + 详情 Table 的主从布局 | 同时看到当前应用与其格式，切换成本低 |
| 一次更改多种格式 | 连续/离散多选、目标兼容性预检、逐项反馈 | 原生表格多选 + 复用更换 Sheet | 单项和批量采用同一套操作语言 |
| 配置打开接管 | 按应用或类型批量选择后缀，预览、启用、停止并恢复 | 独立侧栏入口 + 分组设置 + 勾选表格 Sheet | 清楚区分配置范围与实际生效状态 |
| 每次选择打开目标 | 选择应用、Chrome 个人资料与窗口/分组、VS Code 窗口 | 独立轻量窗口 + 应用 List + 目标详情 | 按当前应用展开相关选项，保持首屏简洁 |
| 新建临时会话 | 使用全新用户数据目录打开内容 | Chrome 打开位置中的独立选项 | 一步启动干净的浏览会话 |
| 通用多窗口打开 | 查询运行窗口，选择已有窗口或可用的新窗口动作 | 共享窗口选择组件 + 能力提示 | 复用聚焦转发流程，按实际能力呈现结果 |
| 清除用户设置 | 查看影响范围、移除已验证存在的自定义关联、重新查询 | 次级菜单 + 简短确认 Alert | 系统可能重新选择应用，需要解释结果语义 |
| 备份与恢复 | JSON 导出、导入预览、冲突处理、结果详情 | 文件菜单 + `NSSavePanel` / `NSOpenPanel` + Sheet | 符合 Mac 文件操作习惯，恢复前可以检查差异 |
| 某个文件仍打开错误 | 选择文件、检测单文件设置、移除覆盖并复查 | 工具页 + 文件选择器 + 检测结果 Table | 诊断对象是具体文件，路径和权限必须可见 |
| 查看版本与帮助 | 版本、用途、常见问题 | 标准“关于 Openly”窗口与帮助菜单 | 信息轻量且入口固定 |

### 1.2 先修正信息语义

| 概念 | 界面含义 | 数据要求 |
|---|---|---|
| 当前默认应用 | 系统当前解析出的打开应用 | 由有效默认查询确认；显式配置记录仅作为来源之一 |
| 应用声明支持 | 应用元数据声明的文件格式 | 同时解析扩展名、UTType 与 MIME 声明；作为候选依据 |
| 自定义设置 | 已确认存在的用户显式关联 | 与系统当前有效默认分别记录 |
| 未找到默认应用 | 查询成功，但系统没有返回默认应用 | 与读取失败、尚未检查分别展示 |
| 无法读取 | 查询失败，当前状态未知 | 显示原因与重试入口 |
| 单文件打开设置 | 某个具体文件的 OpenWith 覆盖 | 仅报告已检查文件的检测结果 |
| 已接管 | 系统有效默认处理器已指向 Openly 接收器 | 保存接管前默认与核验结果；展示名称统一为 Openly |
| 本次打开目标 | 本次转发的应用与可选个人资料、窗口、分组 | 与系统默认关联分别维护；单次选择保持接管配置 |

显示扩展名便于理解，执行修改时按实际解析的文件类型去重。`.jpg` 与 `.jpeg` 等可能映射到同一 UTType，预览应展示此次操作实际涉及的全部已知别名。无法解析类型时保留条目并解释原因。

## 2. 现状问题与设计响应

| 发现 | 依据 | 对用户的影响 | 重设计要求 |
|---|---|---|---|
| 输入框无法输入、选择应用后不显示后缀已有问题记录 | `Sources/Views/todo.md` | 核心任务无法完成 | 将中文输入、焦点保持、选择联动列为首批验收；根因需实机定位 |
| 主窗口通过普通属性持有模型，Tab 状态缺少对应观察包装 | `ContentView.swift` | 存在状态生命周期与刷新风险 | 明确模型所有权和观察关系，验证重绘后输入与选择稳定；这是排查方向 |
| “刷新”菜单函数为空 | `OpenlyApp.swift: refreshAll()` | 快捷键无实际效果 | 菜单与工具栏调用同一刷新命令 |
| 批量结果直接写入全部成功、失败为零 | `BatchOperationView.swift: apply()` | 失败被误报为成功 | 结果从真实执行记录与核验结果生成 |
| 单项修改错误仅输出日志，选择 Sheet 仍关闭 | `ExtensionListViewModel.swift`、`ExtensionListView.swift` | 用户无法判断是否生效 | 失败保留目标与上下文，显示原因和重试 |
| 应用详情只遍历声明支持的格式 | `AppListView.swift: appExtensionsDetail()` | 已默认关联但未声明支持的格式可能缺席 | 详情采用声明支持与有效默认集合的并集，并标明来源 |
| 扫描器过滤掉无法提取格式的应用 | `AppScanner.swift: parseApp()` | “已安装应用”口径不完整 | 展示实际扫描范围；允许显示格式声明未知的应用 |
| 列表主要依赖 LSHandlers 与描述库补全 | `LaunchServicesReader.swift`、`ExtensionListViewModel.swift` | 缺少显式记录可能被显示成“未关联” | 查询有效默认，区分未知、无默认与自定义设置 |
| 清除关联通过直接写 plist 实现 | `LaunchServicesWriter.swift: clearAssociation()` | 清除后的系统选择和生效情况需核验 | “移除自定义设置”须以实现验证为前提，再查询实际默认 |
| 两个视图分别持有数据与服务 | 两个 ViewModel | 一处修改后另一处可能保留旧值 | 共用关联数据源和操作结果广播 |
| 导入执行后只输出日志，跳过数与总数统计单位不同 | `OpenlyApp.swift`、`ConfigService.swift` | 无法核对恢复范围与结果 | 导入先预览，统计统一按归一化文件类型计算 |
| xattr 有服务实现，主界面缺少调用入口 | `XattrService.swift`、现有 Views | README 中的能力难以使用 | 增加“检查文件”入口，检测用户明确选择的文件 |

界面改造须与数据、状态修复配套。先保证状态可信，再调整布局与视觉。

## 3. 信息架构与窗口

```text
Openly 主窗口
├─ 文件类型（默认入口）
│  ├─ 搜索 / 分类 / 默认应用来源
│  ├─ 文件类型表格 / 多选
│  └─ 更换默认应用 Sheet
├─ 应用
│  ├─ 应用列表 / 搜索 / 来源筛选
│  └─ 应用详情 / 格式筛选 / 多选修改
├─ 打开接管
│  ├─ 后缀接管 / 按应用或类型添加 / 停止与恢复
│  ├─ 网页链接接管
│  └─ 应用打开能力 / 权限状态
└─ 工具
   └─ 检查文件

文件菜单：导入配置… / 导出配置…
视图菜单：刷新 / 显示或隐藏边栏
Openly 菜单：关于 Openly
帮助菜单：打开方式说明

系统打开事件 → 独立轻量选择器 → 应用 → 打开目标 → 转发
```

主导航采用固定侧栏。文件类型页使用两栏：导航与表格；应用页在内容区采用应用列表与详情，形成三栏。应用详情直接承载主要操作，文件类型的高级信息通过可收起的检查器查看。

选择侧栏的依据是文件类型、应用、打开接管三个管理入口与辅助工具入口，以及应用页明确的主从关系。现有 TabView 曾出于构建便利采用；新实现先用最小 `NavigationSplitView` 样例验证当前 CLI 工具链，再接入完整数据。原有工具链记录中的宏可用性说法需要以实际构建结果确认。

### 3.1 窗口尺寸与空间分配

以下为本产品设计起点，单位为 pt，实施时以原生控件实际尺寸与可读性校准。

| 项目 | 建议值与行为 |
|---|---|
| 初始窗口 | 1120 × 760，可自由缩放；验证 880 × 600 的紧凑布局 |
| 主侧栏 | 默认 184，可在 168–220 间调整，可由工具栏折叠 |
| 应用列表 | 默认 244，可在 220–300 间调整 |
| 应用详情 | 目标可用宽度至少 440；宽度不足时折叠主导航侧栏 |
| 文件类型表格 | 文件类型与默认应用优先；紧凑时隐藏分类列，详情仍可查 |
| Sheet | 默认约 600 × 520，内容滚动，操作区固定；适配父窗口 |
| 状态栏 | 约 28 高，展示结果数、选中数和最近刷新状态 |
| 轻量打开选择器 | 默认约 720 × 480；应用栏约 200，目标区弹性布局。小屏收为“应用 → 目标”两步，保留返回与选择 |

缩小时搜索可收为系统搜索入口，筛选留在菜单。保留当前选中应用和滚动位置。扩展名、应用名等关键列优先获得宽度；长路径中间省略，可复制完整值或在 Finder 中显示。

## 4. 页面风格与视觉规范

设计方向：内容清晰、控件原生、层级克制。参照 Finder 的列表操作习惯、系统设置的分组信息和 macOS 标准 Sheet，结合每个任务分别使用。

Apple 当前指导将 Liquid Glass 用于导航与控制层，标准 SwiftUI / AppKit 控件可随平台采用相应外观。Openly 在较新系统使用系统提供的工具栏与侧栏表现，macOS 14 使用该版本的原生外观；内容表格保持稳定可读的背景。[Apple：Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)、[Build an AppKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/310/)

| 元素 | 规范 |
|---|---|
| 背景 | 主内容使用系统窗口/文本背景语义色，侧栏交由系统容器处理 |
| 主色 | 系统 AccentColor，跟随用户强调色；主要用于选中与主操作 |
| 文字 | `.primary`、`.secondary`；关键状态采用正文级对比度 |
| 字体 | 系统字体及语义字号；页面标题 `.title2`，分组 `.headline`，表格 `.body`，辅助说明 `.callout` / `.caption` |
| 技术文本 | 扩展名、UTType、Bundle ID 使用等宽字体；中文说明沿用系统正文 |
| 间距 | 基础 4、8、12、16、24、32；页面内边距 20–24，区域间距 16–24 |
| 表格密度 | 行高起点 32–36，应用列表行高 44–48；字号增大时随内容增长 |
| 表格外观 | 原生表头、列分隔与可选交替行底色；支持排序；分类显示简短文本 |
| 图标 | 结构与操作使用 SF Symbols；应用身份图标由系统读取，保持原样与比例 |
| 按钮 | 工具栏按钮、标准边框按钮；Sheet 只突出一个提交动作 |
| 状态色 | 成功、警告、失败同时使用文字与图标；选中行内保持可辨识 |
| 动效 | 侧栏、Sheet、焦点使用系统行为；状态切换克制，尊重“减少动态效果” |
| 外观适配 | 浅色、深色、提高对比度、减少透明度分别验收 |

SF Symbols 建议：文件类型 `doc.text`，应用 `square.grid.2x2`，检查文件 `doc.text.magnifyingglass`，刷新 `arrow.clockwise`，更换 `arrow.triangle.2.circlepath`，高级信息 `info.circle`。实现时核对最低支持系统的符号可用性。

桌面交互采用原生 regular 控件和完整行选择热区。ui-ux-pro-max 中的移动端触控尺寸、网页字体和手机断点按平台语义调整；Mac 以指针可点选、键盘可操作、文字可读为验收依据。

## 5. 页面线框图与交互

图中 `[文字]` 为按钮或输入框，`▼` 为菜单，`●` 为选中状态；图标位置以文字表达。线框图说明信息层级与操作位置，实际控件采用系统绘制。

### 5.1 文件类型主页面

```text
┌────────────────────────────────────────────────────────────────────────────────┐
│ 窗口控制  [边栏]  文件类型                [刷新] [更换默认应用…] [搜索         ] │
├───────────────┬────────────────────────────────────────────────────────────────┤
│ 管理          │ 分类 [全部 ▼]   默认应用 [全部 ▼]                   [清除筛选] │
│ ● 文件类型    ├──────────┬──────────────────────┬────────────────┬─────────────┤
│   应用        │ 文件类型 ↑│ 说明                 │ 默认应用       │ 分类        │
│               ├──────────┼──────────────────────┼────────────────┼─────────────┤
│   打开接管    │ .pdf     │ PDF 文档             │ 预览           │ 文档        │
│ 工具/检查文件 │ .jpg     │ JPEG 图像            │ 图像编辑器     │ 图像        │
│               │ .md      │ Markdown 文本        │ 编辑器         │ 文本        │
│               │ .xyz     │ 类型说明待补充       │ 未找到默认应用 │ 其他        │
│               │ …        │                      │                │             │
├───────────────┴──────────┴──────────────────────┴────────────────┴─────────────┤
│ 显示 128 / 655 种格式 · 已选 2 种                         更新于 14:32 [详情]   │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 默认按扩展名升序；支持按说明、默认应用和分类排序，刷新保留排序。
- 搜索支持 `pdf`、`.pdf`、中文描述和应用名；搜索与分类、默认应用来源筛选共同生效。
- “默认应用”筛选明确列出：全部、系统应用、第三方应用、未找到默认应用、无法读取。筛选名称表达的是默认应用来源。
- 单击选择一行，Command 单击离散多选，Shift 单击连续多选。工具栏按选中数量显示“更换默认应用…”或“更换 8 种格式的默认应用…”。
- 双击打开该行的更换 Sheet；右键菜单提供更换、查看详细信息、移除自定义设置。右键未选中行时先将其设为操作目标。
- 搜索或筛选改变时，选择集合收敛到仍可见的行；底部同步显示选中数量，防止隐藏条目被批量修改。
- 详情检查器显示扩展名、类型标识、已知别名、默认应用完整信息、查询来源与时间；高级字段可折叠。
- 已接管行显示“Openly · 每次选择”，右键提供“管理接管…”；多选菜单提供“交给 Openly 接管…”，带入接管预览。将已接管类型直接更换为其他默认应用时，预览明确显示“停止接管并设为所选应用”，生效后同步接管状态。
- 没有结果时保留搜索和筛选，显示“未找到匹配的文件类型”，提供“清除筛选”。

### 5.2 更换默认应用 Sheet：单项与批量共用

```text
┌──────────────────────────────────────────────────────────────┐
│ 更换默认应用                                                 │
│ 已选 3 种格式 · 将影响 2 个文件类型              [查看范围 ▼] │
│ .jpg、.jpeg、.png                                             │
│ 搜索应用 [                                             ]     │
├──────────────────────────────────────────────────────────────┤
│ 推荐应用                                                     │
│ ● [应用图标] 预览                       支持全部所选类型     │
│ ○ [应用图标] 图像编辑器                 支持全部所选类型     │
│ 其他应用                                                     │
│ ○ [应用图标] 编辑器                     支持情况待确认       │
│                                         [选择其他应用…]     │
├──────────────────────────────────────────────────────────────┤
│ 修改预览：当前应用 → 预览                   [展开 2 项变化]  │
│                                  [取消] [设为默认应用]      │
└──────────────────────────────────────────────────────────────┘
```

1. 打开时冻结选中项快照，解析实际类型与别名，生成修改预览；单项直接显示“当前应用 → 目标应用”。
2. 单击应用只改变候选选择，提交按钮执行写入。目标与当前默认相同的类型记为“无需更改”。
3. 推荐区优先显示已声明支持全部目标类型的应用；其他应用提供“已声明支持 x/y”或“支持情况待确认”。通过系统文件选择器补选 `.app`，随后校验路径与应用身份。
4. 支持情况不足时展开受影响清单；用户明确选择“仍使用此应用”后才允许提交这些条目。类型无法解析、应用不存在等阻断项单列，允许移除后继续。
5. 提交前重新检查目标和当前关联。若与预览不同，更新差异并要求重新提交，防止覆盖过期状态。
6. 执行期间显示“正在处理 2 / 8”，禁用重复提交和目标切换；提供“停止后续操作”，当前系统调用结束后停止。
7. 单项经核验成功后关闭 Sheet，在主窗口状态区域显示结果；失败保留 Sheet、目标和错误。批量进入结果页。
8. 提交前 Escape 与“取消”等效，关闭后焦点回到触发按钮或原行。

| 窗口内标签组 | 先选已有窗口，再选“普通标签页”或当前窗口内已打开的组；组名、颜色文字和数量共同识别 |

切换 Profile 后清空窗口与组选择；切换窗口后清空组选择。默认标签组为“普通标签页”。提交时复查目标 Profile、窗口、组是否有效；组已关闭时提示改选，保留链接。

浏览器基础动作与高级连接状态分开展示。高级能力不可用时，窗口／分组区域显示“连接 Chrome 以选择窗口和标签组”及设置入口；基础动作继续可用。无痕已有窗口与分组仅在扩展具备无痕访问能力时呈现。若仅有通用窗口查询，提供下节的“兼容打开”，并以窗口标题展示可确认的信息。

Edge 通过共享 Chromium 适配验证后使用相同布局，个人资料与窗口数据按浏览器隔离。高级模式能力和桥接方式以[技术报告](open-routing-feasibility.md)为依据。

### 5.12 VS Code 与通用多窗口兜底

```text
┌────────────────────────────────────────────────────────────────────┐
│ 打开 notes.md                                                      │
├─────────────────────┬──────────────────────────────────────────────┤
│ 搜索应用 [        ] │ Visual Studio Code                           │
│   文本编辑          │ ○ 新窗口                                     │
│ ● VS Code         › │ ○ 最近活动窗口                               │
│   其他应用…         │ ● 指定窗口                         [刷新]    │
│                     │   ● Openly · native-ui-redesign.md           │
│                     │   ○ 项目 A · README.md                       │
│                     │   ○ 未命名窗口                               │
│                     │                                              │
│                     │ 将先切换到所选窗口，再打开文件。             │
├─────────────────────┴──────────────────────────────────────────────┤
│ VS Code › Openly                               [取消] [在此窗口打开]│
└────────────────────────────────────────────────────────────────────┘
```

VS Code 的已有窗口方案沿用已通过简单测试的“聚焦目标 → CLI 复用打开”；新窗口使用对应 CLI 动作。辅助功能未授权时，目标区显示“授权后选择已有窗口”和“前往系统设置”，新窗口与最近活动窗口按可用能力保留。文件夹使用新窗口动作，复用工作区的行为按技术报告单独处理。

**推广到其他多窗口应用：** 所有候选应用共用窗口发现与选择组件。发现多个普通内容窗口即提供窗口列表；单个窗口也可选，零窗口显示默认打开与已支持的新窗口动作。过滤菜单、面板和对话框；窗口以会话对象定位，标题、位置和最小化状态辅助区分，同名窗口保留独立行。列表获取失败与“没有窗口”分别呈现。

| 能力层级 | 选择器行为 | 执行方式与结果 |
|---|---|---|
| 专用目标接口 | “在此窗口打开” | 应用 CLI、脚本或扩展定向路由；按接口能力确认提交或完成 |
| 通用窗口兼容 | “尝试在此窗口打开”，显示“兼容打开”说明 | 聚焦所选窗口后，显式向该应用发送打开请求；最终位置由目标应用处理 |
| 新窗口能力 | “新窗口” | 使用已验证的应用命令或语义化原生菜单动作，再转发内容 |
| 基础打开 | “默认打开” | 显式指定应用，由应用决定展示位置 |

通用兼容向所有可读取窗口的候选应用开放，优先使用已验证的定向接口，其次采用聚焦转发。用户首次选择“兼容打开”时就地提示“应用可能自行决定打开位置”，提交仅报告请求已交付；用户可反馈“打开到了其他窗口”，标记该应用版本的兼容结果，后续优先提供基础动作。

“新窗口”能力独立检测并按应用维护；可通过已验证的 CLI、脚本或原生“新建窗口”菜单动作轻量适配。macOS 的新应用实例参数用于进程启动，其语义与创建内容窗口不同，窗口动作以应用验证结果为准。

点击打开后收起选择器，定位并激活目标窗口，短暂确认焦点再转发。权限被撤销、目标消失、聚焦超时则返回原选择器；用户切换到其他窗口时重新检查目标。窗口发现、焦点观察和适配连接均按请求创建与释放。简单兼容承担广覆盖，精确 Profile／分组选择继续由专用适配保证语义。

### 5.13 接管与现有功能联动

- **默认应用管理：** 文件类型和应用视图、接管管理页共享实际关联状态；接管前应用作为恢复资料显示，本次打开应用作为临时路由选择保存。
- **单文件设置：** 类型已接管而某文件仍直接打开时，从“检查文件”核对单文件覆盖，并提供“查看该类型接管状态”。
- **导入导出：** 配置增加接管目标及已验证的能力偏好。接管前默认用于本机恢复；跨设备导入时以目标机器当前默认重新建立恢复记录。导入预览按“直接默认关联／交给 Openly 接管”区分，同一类型选定一个最终动作。旧版配置继续按原有直接关联语义处理。
- **恢复入口：** 关闭管理窗口后接管仍由系统按需唤起；停止接管通过管理页显式恢复。停用前提供“停止全部接管…”并逐项显示恢复结果，失败项继续可管理。

## 6. 共用状态、反馈与键盘

### 6.1 数据与操作状态

```text
首次进入 → 读取中 → 可用数据 / 部分可用 / 读取失败
可用数据 → 后台刷新 → 更新成功 / 保留旧数据并标记刷新失败

选择目标 → 预检 → 等待提交 → 执行 → 读取验证 → 结果
                    ↑                      │
                    └────修正目标 / 重试────┘
```

首次加载显示具体任务文字与进度指示；再次刷新保留旧列表、选择与滚动位置。部分来源读取失败时展示其余可用数据，并在对应区域标记未知状态。主动刷新应使扫描缓存失效或明确重新扫描范围。

同一窗口内的写入串行执行。关闭执行中的 Sheet 时解释“当前操作完成后停止，已完成项会保留”，用户可继续等待或停止后续操作；关闭主窗口或退出应用沿用同一任务规则。操作结束后先保存结果，再释放任务状态。

每项结果至少包含：类型标识、展示扩展名、操作前有效默认、目标应用、执行状态、系统错误、核验状态与时间。UI 直接消费结果，原始错误可展开或复制。

单项成功使用就地反馈；批量结果在 Sheet 中保留至“完成”，关闭后可从本次会话状态栏“查看上次结果”重开。需要决策或中止的错误使用 Alert；普通读取错误在内容区提供重试。Apple 的 Alert 指导强调用于重要状态与必要决策，避免以重复弹窗替代日常反馈。[Apple：Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)

### 6.2 快捷键与焦点

| 操作 | 行为 |
|---|---|
| Command-F | 聚焦当前页面主搜索；应用页格式搜索可通过 Tab 进入 |
| Command-R | 执行与刷新按钮相同的命令，进行中时合并重复请求 |
| Command-A | 焦点在表格时选择全部可见行；焦点在文本框时选择文本 |
| Command-Shift-S / Command-Shift-O | 导出 / 导入配置，与现有代码保持一致 |
| 方向键 | 移动列表选择，应用详情跟随所选项更新 |
| Tab / Shift-Tab | 按视觉顺序遍历控件，遵循系统键盘导航设置 |
| Return | Sheet 中触发可用默认按钮；输入法组合状态先完成文字输入 |
| Escape | 取消尚未执行的 Sheet；执行中按任务停止规则处理 |

搜索不得因过滤、加载或重绘失去焦点。支持中文输入法组合、粘贴、全选与清空；筛选只读取已稳定的输入状态，必要时对较重过滤短暂防抖。模态打开时聚焦搜索或首个必要字段，关闭后恢复原焦点。

轻量选择器首次聚焦应用搜索，方向键选择应用，Tab 进入目标区；窗口列表支持方向键与空格选择，Return 在目标有效时提交，Escape 取消本次请求。Chrome 的 Profile、位置和标签组按视觉顺序遍历。打开成功后的焦点留在目标应用；失败返回选择器并恢复原目标行。

### 6.3 可访问性

- 图标按钮有中文可访问名称与 tooltip；重复装饰图标从朗读顺序隐藏。
- 表格朗读列名、扩展名、默认应用与状态；结果摘要以完整句子播报，避免每项完成都打断输入。
- 失败、选中和警告同时由文字与形状表达；浅色、深色下正文目标对比度至少 4.5:1。
- 窗口缩小或字号增大时操作区可见，焦点所在行自动滚入可视区域。
- “减少动态效果”降低过渡；“减少透明度”与“提高对比度”交由语义色和系统材质正确响应。

### 6.4 接管的加载与转发状态

```text
收到请求 → 缓存应用候选可交互 → 按需加载目标 → 用户确认
         → 复查目标 → 聚焦 / 调用 → 已提交 / 可确认完成 / 失败 / 结果待确认
```

接收器和管理界面分离，选择器首帧加载缓存、当前请求及基础动作。完整应用扫描、所有 Profile 窗口枚举和浏览器连接在用户进入相关目标后执行；耗时区域使用局部进度与取消。切换应用或关闭选择器时取消旧查询，过期结果按请求及选择版本丢弃。

基础模式在队列完成后退出，管理窗口可独立关闭；窗口监听只覆盖本次选择及转发。浏览器桥接的唤醒、短连接与可选常驻成本，以及冷启动和空闲资源指标，按[技术报告的性能方案](open-routing-feasibility.md)验收。列表刷新保留当前目标，目标失效时提示重选；已提交但结果不明的请求保持可核对状态，用户确认后再决定重试。

## 7. 实施顺序与验收

### 7.1 推荐实施顺序

1. **修复可信性基础。** 复现输入和应用选择问题；统一模型生命周期、有效默认读取、数据共享、刷新命令和真实结果统计。
2. **搭建原生导航与两张主页面。** 最小构建验证分栏容器，接入表格、搜索、筛选、选择和紧凑窗口布局。
3. **统一修改流程。** 共用单项/批量 Sheet、预检、类型去重、提交与核验，接入逐项错误和重试。
4. **实现打开接管。** 后缀按应用／类型选择、接管与恢复、网页链接接管、轻量选择器及请求队列；接入 VS Code 和通用窗口兼容能力。
5. **完善高级目标与辅助功能。** Chrome 个人资料、窗口、标签组与临时隔离会话；导入预览、导出反馈、文件检测与自定义设置移除，按能力验证结果开放。
6. **完成视觉和交互验证。** 浅深色、中文输入、VoiceOver、系统辅助设置、长内容、多选、最低系统兼容及接管冷启动与空闲资源。

### 7.2 可执行验收清单

| 验收场景 | 通过标准 |
|---|---|
| 搜索输入 | 连续中文输入、候选词确认、粘贴和退格正常；筛选更新后仍保有焦点 |
| 应用选择 | 鼠标与键盘均能切换详情；显示正确应用的格式并清空旧选择 |
| 数据语义 | 缺少显式记录、没有有效默认、查询失败三种情况显示不同状态 |
| 格式集合 | 应用未声明但已默认指向它的格式仍可见；大小写和前导点归一化 |
| 单项更换 | 候选选择阶段保持原关联；提交后验证成功才显示已生效 |
| 失败反馈 | 应用移除、类型未知、系统拒绝均显示具体原因，保留重试上下文 |
| 批量部分失败 | 注入成功、失败、待验证和停止场景，统计与每项记录一致 |
| 同类型别名 | 同 UTType 多扩展名只写入一次，预览显示已知受影响别名 |
| 多选与筛选 | Command/Shift 多选正常，筛选后的操作仅涉及可见选中项 |
| 页面一致性 | 文件类型页修改后应用页立即获得同一有效状态；反向修改亦然 |
| 主动刷新 | 工具栏与快捷键行为一致，保留搜索、排序和选择，能发现新安装应用 |
| 清除设置 | 以验证后的实际默认展示结果；清除失败与结果未确认可区分 |
| 导入 | 无效 JSON、未知版本、缺失应用和冲突记录均在写入前处理 |
| 单文件检查 | 有覆盖、无覆盖、无权限、文件失效分别呈现；操作后重新检测 |
| 窗口与外观 | 880 × 600、1120 × 760 和放大窗口下可完成主要任务；浅深色信息完整 |
| 可访问性 | VoiceOver 能识别页面、选择、按钮、错误；键盘可完成更换与导入 |
| macOS 兼容 | 在最低支持系统与当前开发系统分别验证构建产物和关键系统调用 |
| 接管后缀选择 | 按应用／类型切换共用选择集；全选只影响当前结果，跨筛选已选数量与清单一致 |
| 接管生效与恢复 | 别名范围提前显示；启用、停止、部分失败分别核验；外部已改关联保留当前值 |
| 网页接管 | HTTP/HTTPS 分别核验，系统拒绝或部分成功可恢复；选择目标后显式转发到应用 |
| 选择器与管理分离 | 管理窗口关闭后仍能接收请求；取消本次打开保持接管设置；选择器首屏不等待完整扫描 |
| Chrome 目标 | Profile 切换清空窗口／组，窗口切换清空组；普通、无痕和扩展权限状态正确 |
| Chrome 目标失效 | 窗口或组在确认前关闭时保留请求并要求重选；显示的组仅来自当前 Profile 与窗口 |
| 新建临时会话 | 每次使用独立的新用户数据目录，当前内容正确打开，日常 Profile 保持原状 |
| VS Code 多窗口 | 正常、同名、最小化、不同桌面窗口均按选中对象聚焦；焦点失败返回选择器 |
| 通用窗口兼容 | 可读内容窗口均可选择；专用路由与兼容打开文案不同；新窗口动作仅按能力提供 |
| 权限与能力缺失 | 拒绝辅助功能或浏览器连接后基础打开仍可用，原请求保留，界面显示下一步 |
| 多项与连续请求 | 当前确认范围稳定，新请求排队；部分失败保留未完成项，已提交项避免重复转发 |
| 接管配置导入 | 同类型关联与接管动作冲突在预览处理；本机恢复记录按导入时当前默认建立 |
| 接管性能 | 测量选择器可交互、目标查询、转发分段耗时；基础空闲进程退出，窗口查询按需进行 |

优先用隔离的测试文件类型与可控服务结果验证写入流程，再在测试环境核对系统实际行为。界面预览与视觉验收覆盖成功、部分失败、空数据、长应用名和大批量数据。
